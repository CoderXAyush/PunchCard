# REVIEW.md: Code Review of Starter `app/main.py`

## Part A: PR Review Findings

The following table documents the defects identified in the starter application across helper functions, database configuration, concurrency handling, and endpoint implementations.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Global config (`load_dotenv`) | `.env` file can overwrite real environment variables or default to hardcoded URI | Running `MONGO_URI="mongodb://custom:27017" uvicorn app.main:app` while `.env` exists connects to `.env` target instead of the supplied environment variable | Use `load_dotenv(override=False)` so process environment variables always take precedence over local `.env` |
| 2 | `MongoClient` initialization & `/health` | `MongoClient` created with default naive datetimes (`tz_aware=False`), and `/health` returns static `{"status": "ok"}` without pinging MongoDB | `GET /health` returns 200 even when MongoDB is offline; subtracting naive Mongo datetimes from aware Python datetimes raises `TypeError: can't subtract offset-naive and offset-aware datetimes` | Pass `tz_aware=True` to `MongoClient`; issue `db.command("ping")` inside `/health` and return HTTP 503 on connection failure |
| 3 | Database connection & startup | App crashes at startup if MongoDB is unreachable during module import / index creation | Starting the app when MongoDB is temporarily down crashes the process before `/health` can serve 503 readiness probes | Ensure client initialization and index creation handle exceptions gracefully; allow app to boot and let `/health` report 503 |
| 4 | Index creation (`ensure_indexes`) | Missing critical compound indexes and presence of redundant single-field indexes | Concurrency races occur; list attendance and punch-out scans degrade to `COLLSCAN` on large collections | Create required compound indexes idempotently at startup: `employees`: `unique: emp_code`, `(department, emp_code)`, `(department, joined_on)`; `attendance_logs`: `unique: (emp_code, date)`, `(emp_code, punch_in desc)`, `(date desc, emp_code asc)`. Removed redundant single-field indexes |
| 5 | Epoch milliseconds validation (`EpochMillis`) | Permissive integer parsing accepts booleans, floats, strings, and seconds-sized timestamps | Sending `{"punched_at": True}`, `{"punched_at": 1715000000}`, or `{"punched_at": 1783312500000.5}` is accepted instead of failing with 422 | Added strict Pydantic `BeforeValidator` enforcing `isinstance(v, int) and not isinstance(v, bool)` and range `[100000000000, 4102444800000]` |
| 6 | Instant truncation (Rule R1) | Instants were not truncated to whole seconds before calculation and storage | Sending timestamp `1783312500900` (09:40:00.900 IST) calculates `600.9s > 600s` grace, erroneously marking the employee 10 minutes late | Implemented `trunc_ms(ms) = (ms // 1000) * 1000` and zeroed microseconds on all datetime conversions before processing or storing |
| 7 | Overnight shift date assignment (Rule R1) | Date assignment used calendar date of punch-in rather than shift-start date | Punch-in at 05:00 IST on 2026-07-07 for shift 22:00–06:00 assigned `date="2026-07-07"` instead of `"2026-07-06"` | Implemented `attendance_date_for_punch`: for overnight shifts (`shift_end <= shift_start`), if punch IST time is earlier than `shift_end`, subtract 1 day from the calendar date |
| 8 | Late calculation boundary (Rule R2) | Late grace check used `>= 600` or counted minutes after grace rather than from shift start | Punch-in at exactly 09:40:00 IST for a 09:30 shift returned `late_minutes = 10` instead of `0` | Strictly enforce `delta <= 600 -> 0`, and when `delta > 600` return `int(delta // 60)` from `shift_start` |
| 9 | Overtime threshold (Rule R3) | Overtime counted durations under 30 minutes or used strict inequality `> 30` | Punch-out at 19:00 for shift end 18:30 (30 min) returned `0` instead of `30`, or punch-out at 18:55 returned `25` instead of `0` | Enforce `return mins if mins >= 30 else 0` where `mins = int((punch_out - shift_end).total_seconds() // 60)` |
| 10 | Work hours rounding (Rule R4) | Used Python's default Banker's rounding (`round()`) or binary float operations | 3618 seconds (1.005 hours) rounded to `1.0` instead of `1.01` due to round-half-to-even and float binary precision error | Implemented `compute_work_hours` using `Decimal(str(secs)) / Decimal("3600")` quantized with `ROUND_HALF_UP` to 2 decimal places |
| 11 | Half-day threshold evaluation (Rule R5) | `half_day` checked raw unrounded work hours rather than rounded work hours | A shift of 4.495 hours (rounds to 4.50) marked `half_day = True` because `4.495 < 4.50` | Evaluate `half_day = work_hours < 4.50` on the already rounded `work_hours` value |
| 12 | Duplicate employee creation race (`POST /employees`) | Check-then-insert pattern without unique index or unhandled `DuplicateKeyError` | Concurrent requests creating the same `emp_code` both returned 201 or caused unhandled 500 | Backed `emp_code` with a unique index, caught `DuplicateKeyError`, and returned HTTP 409 |
| 13 | Punch-in concurrency race (`POST /attendance/punch-in`) | Relied on application `find_one` check before insertion | Two concurrent punch-ins for the same employee and date both succeeded with 201 | Enforced unique compound index on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409 |
| 14 | Punch-out concurrency race (`POST /attendance/punch-out`) | Read record then updated without checking `punch_out is None` atomically | Two concurrent punch-outs for the same open record both succeeded with 200 | Performed atomic `update_one({"_id": rec["_id"], "punch_out": None}, ...)`: if `modified_count == 0`, re-read and return HTTP 409 |
| 15 | History lost updates in regularization (`PATCH /attendance/{emp_code}/{date}`) | In-memory history append followed by unconditional `$set` overwritten concurrent edits | Concurrent regularizations silently overwrote each other's audit history entries | Used optimistic concurrency control with `update_one` conditioned on history length (`$expr: {$eq: [{$size: {$ifNull: ["$history", []]}}, n]}`) using `$push`, retrying up to 5 times before returning 409 |
| 16 | Internal MongoDB `_id` leaking | Raw MongoDB documents returned directly in responses | Responses contained `_id: ObjectId(...)`, causing JSON serialization errors (500) or contract violations | Excluded `_id` via projection `{"_id": 0}` and serialized documents through sanitizers converting BSON types to API contract formats |
| 17 | Handling missing fields in legacy documents | Serializer failed on documents lacking optional fields like `history` or `half_day` (e.g., sample document 9) | Missing fields in seeded records caused serialization failure or violated required response fields in OpenAPI | Provided explicit defaults in serialization: `half_day: False` and `history: []` when absent or null |
| 18 | Regularization changes diff accuracy | History logged unchanged fields and compared datetime objects with milliseconds improperly | Modifying reason without changing status logged `status: {from: 'PRESENT', to: 'PRESENT'}` in `changes` | Compared normalized before-and-after values and only included keys where values actually changed; stored BSON datetimes internally and epoch ms in API |
| 19 | Pagination total count ignoring query filters | `total` calculated via `count_documents({})` rather than `count_documents(q)` | `GET /employees?department=Engineering` returned total count of all employees instead of matching department count | Passed query filter `q` into `count_documents(q)` for all paginated endpoints |
| 20 | Unsafe regex query matching | Department filter used `{"$regex": dept}` instead of exact string match | Passing regex metacharacters (e.g. `.*` or catastrophic patterns) led to unintended matches or performance degradation | Changed to exact match `{"department": dept}` per OpenAPI contract |
| 21 | Bare `except:` clauses | Bare exception handling masked syntax and system errors | Unexpected runtime errors swallowed or converted into obscure responses | Replaced bare `except:` with explicit exception types (`DuplicateKeyError`, `ValueError`, `PyMongoError`) |

## Examined and Fine

The following architectural and implementation details were reviewed and determined to be correct per design:

1. **String Representation for Calendar Dates and Times**:
   - `date` (`YYYY-MM-DD`), `joined_on`, and shift times (`HH:MM`) are preserved as strings rather than converted to datetimes. This prevents artificial timezone conversions on pure calendar concepts and aligns with `DATA_MODEL.md`.
2. **Instant Storage as UTC BSON Datetimes**:
   - Punch times, creation times, and audit timestamps are converted from epoch milliseconds to UTC BSON datetimes when persisted in MongoDB, and converted back to epoch milliseconds at the API boundary.
3. **Audit History Immutability**:
   - `history` is strictly append-only. Original punch-in and punch-out events intentionally never write to history, reserving the log exclusively for manual corrections (`PATCH`).
4. **FastAPI Pydantic Error Format**:
   - Validation errors properly emit HTTP 422 with FastAPI's standard `{"detail": [...]}` format, adhering to the OpenAPI error contract.
